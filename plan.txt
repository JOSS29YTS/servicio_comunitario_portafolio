# PLAN MAESTRO: SISTEMA DE GESTIÓN ESCOLAR LOCAL (RED LAN)

## 📌 Resumen de la Arquitectura
- Tipo de Red: Local (100% libre de costos de servidores en la nube como Render o Supabase).
- Tecnologías: React (Frontend) + Node.js/Express (Backend) + MySQL (Base de datos).
- Capacidad de archivos: PDFs de ~10 MB guardados localmente.
- Seguridad: Copias de seguridad automáticas diarias sincronizadas con Google Drive.

---------------------------------------------------------
## 🖥️ Configuración por Computadora

### 1. PC de la Directora (El Servidor Central)
Esta computadora debe permanecer encendida durante la jornada escolar ya que almacena el "cerebro" del sistema.

Infraestructura instalada:
- MySQL Server: Base de datos relacional para los registros del colegio. Se mantiene configurada por defecto (localhost / 127.0.0.1) por seguridad.
- Node.js: El backend unificado que gestiona los datos, procesa las subidas de archivos mediante multer y sirve la interfaz visual de React.
- Google Drive para Escritorio: Sincroniza la carpeta de respaldos local con la nube.

Automatización de arranque (Inmortal):
- El backend de Node.js se configura como un Servicio de Windows (usando qckwinsvc o PM2). Se enciende solo al prender el CPU, incluso antes de iniciar sesión en Windows.

Cómo trabaja la Directora:
- Abre el sistema mediante un Acceso directo de Chrome en su escritorio configurado con la opción "Abrir como ventana". Se abrirá una interfaz limpia a través de http://localhost:3000.

### 2. PCs de la Subdirectora y el Profesor (Los Clientes)
Estas computadoras no requieren instalación de código, bases de datos ni motores de ejecución.

Configuración:
- Están conectadas a la misma red Wi-Fi o cable de red que la PC de la Directora.

Cómo trabajan:
- Abren el navegador Chrome e ingresan la IP local fija de la Directora (ejemplo: http://192.168.1.50:3000).
- Crean un Acceso directo de Chrome ("Abrir como ventana") en sus escritorios. Visualmente se verá exactamente igual a una aplicación instalada nativa (.exe).

---------------------------------------------------------
## 📂 Flujo de Trabajo Diario

1. Recepción: La Directora recibe los correos, descarga los PDFs a su computadora.
2. Registro: Abre el sistema, rellena el formulario de React y adjunta el PDF. Al enviar, viaja por la red interna en formato FormData hacia Node.js.
3. Procesamiento: Node.js recibe el PDF. Para evitar duplicados y facilitar búsquedas manuales futuras, le asigna un nombre combinando la fecha y la cédula/ID del alumno (ej: 20260516-12345678-acta.pdf) y lo guarda en la carpeta local `archivos_colegio`.
4. Almacenamiento: Node.js guarda la información del alumno y la URL local del archivo en MySQL.
5. Automatización 4 PM: Un script .bat extrae un respaldo de MySQL, copia los PDFs y Google Drive lo sube a la nube.

---------------------------------------------------------
## 🔒 Plan de Blindaje y Copias de Seguridad (Arquitectura Segura)

Para garantizar que el sistema nunca deje de funcionar y los datos estén a salvo de cualquier accidente físico o ataque de red:

1. IP Estática Configurada en Windows: Como no hay acceso administrativo al router del colegio, se configurará la IP fija directamente desde los ajustes de Red de Windows en la PC de la Directora. Se elegirá una IP fuera del rango habitual de asignación automática (ej: 192.168.1.200) para evitar conflictos, garantizando que el servidor siempre responda en la misma dirección.
2. Apertura de Firewall Segura: Se crea una regla de entrada en el Firewall de Windows de la Directora para permitir tráfico libre ÚNICAMENTE en el puerto 3000 (Node.js). MySQL permanece cerrado y blindado tras el firewall, aceptando peticiones únicamente de Node.js de forma interna.
3. Protección Eléctrica: La PC de la Directora debe contar idealmente con un UPS para evitar corrupción de la base de datos ante apagones repentinos.
4. Respaldo en la Nube Automatizado con Logs: Un archivo .bat programado con el Programador de Tareas de Windows se ejecuta solo todas las tardes a las 4:00 PM. Este extrae la base de datos con mysqldump, copia la carpeta de PDFs y lo deposita en la unidad virtual de Google Drive (G:\Mi unidad\Respaldos_Colegio).
   * Mejora Implementada: El script .bat registrará su actividad en un archivo de texto (`backup_log.txt`) para tener un historial comprobable de si las copias se hicieron con éxito o si hubo algún error.

---------------------------------------------------------
## 🚀 Ventajas del Enfoque

- Mantenimiento Centralizado: Si el próximo año necesitas agregar un botón o corregir un texto en la interfaz visual, solo compilas React y reemplazas la carpeta `build` en la PC de la Directora. La Subdirectora y el Profesor verán los cambios instantáneamente al día siguiente sin reinstalar nada.
- Independencia de Internet y Alta Velocidad: Si el internet del colegio se cae, el sistema seguirá registrando alumnos y abriendo PDFs normalmente y a velocidades de red Gigabit, sin los cuellos de botella de subida de las nubes públicas. Solo la sincronización final de Google Drive esperará a que vuelva el internet.
